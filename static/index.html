02 How a check works

The real token chain, walked by api/checker.py:

1
Microsoft login

GET login.live.com/oauth20_authorize.srf, parse the PPFT token + urlPost, POST the credentials.

2
Token exchange

Microsoft returns an access_token (RPS ticket) in the OAuth redirect fragment. Wrong password → BAD, 2FA page → 2FA.

3
Xbox → XSTS auth

RPS ticket → user.auth.xboxlive.com → XBL JWT → xsts.auth.xboxlive.com → XSTS token. XErr 2148916229 → BANNED.

4
Probe & report

Profile (gamertag/gamerscore), subscriptions API, store purchases, Minecraft entitlements, Microsoft account services → PREMIUM or FREE.

05 Signature verification

Every /check response carries watermark + signature — HMAC-SHA256 over the canonical JSON of the payload (keys sorted, compact separators, signature excluded). Anyone holding the server’s WATERMARK_SECRET can prove the response wasn’t tampered with. The console above verifies it live in your browser with Web Crypto.

# verify a signed response (Python, stdlib only)
import hashlib, hmac, json

def verify(payload: dict, secret: str) -> bool:
    provided = payload.pop("signature", None)
    expected = hmac.new(
        secret.encode(),
        json.dumps(payload, sort_keys=True, separators=(",", ":")).encode(),
        hashlib.sha256,
    ).hexdigest()
    return hmac.compare_digest(provided or "", expected)

07 Responsible use

  • ⚠️ Educational use only. Only check accounts you own or are explicitly authorised to test.
  • ⚠️ Microsoft’s terms restrict automated access — this is a learning demo, not a product.
  • ⚠️ The API has no authentication by design. Don’t expose it publicly without a gateway (rate limiting / API keys).
  • ⚠️ Credential stuffing and unauthorised account checking is illegal in most jurisdictions.
